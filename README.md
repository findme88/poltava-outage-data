# Графіки відключень Полтаваобленерго

Відкритий набір даних про планові погодинні відключення електроенергії
в Полтавській області. Містить графіки на сьогодні та завтра для 12 підчерг
у форматі JSON зі збереженням півгодинних інтервалів.

Джерело даних: [офіційний сайт АТ «Полтаваобленерго»](https://www.poe.pl.ua/).
Проєкт є незалежною неофіційною публікацією даних і не пов'язаний з оператором.

## Доступ до даних

**[Poltavaoblenergo.json](https://raw.githubusercontent.com/findme88/poltava-outage-data/main/data/Poltavaoblenergo.json)**

```text
https://raw.githubusercontent.com/findme88/poltava-outage-data/main/data/Poltavaoblenergo.json
```

Файл доступний без авторизації та API-ключа. Його можна використовувати
для інтеграцій із вебзастосунками, інформаційними панелями та системами
домашньої автоматизації.

```bash
curl --fail --location --max-time 20 \
  https://raw.githubusercontent.com/findme88/poltava-outage-data/main/data/Poltavaoblenergo.json
```

## Актуальність даних

- Перевірка джерела запланована кожні 5 хвилин. Нові графіки та зміни
  публікуються після успішного отримання й перевірки даних.
- Якщо змін немає, час перевірки у файлі оновлюється приблизно раз на годину.
- GitHub Actions може затримувати запуски, а GitHub Raw може кешувати відповіді.
  Інтервал перевірки не є гарантією часу доставки оновлень.
- За недоступності джерела останні підтверджені дані зберігаються.
  Дату й актуальність кожного дня слід перевіряти окремо через `verifiedAt`.

· [Стан автоматичних перевірок](https://github.com/findme88/poltava-outage-data/actions)

## Структура JSON

| Поле | Значення |
| --- | --- |
| `regionId` | Ідентифікатор регіону: `Poltava`. |
| `lastUpdated` | Час останньої успішної перевірки, записаної у публікації, у форматі ISO 8601 UTC. |
| `fact.data` | Графіки за днями. Ключ дня: Unix timestamp опівночі в `Europe/Kyiv`, записаний як рядок. |
| `fact.today` | Unix timestamp опівночі дня, для якого сформовано публікацію. Тип: число. |
| `fact.update` | Локальний час останньої записаної перевірки: `DD.MM.YYYY HH:mm`. Не є часом зміни графіка оператором. |
| `preset.time_zone` | Межі годинних інтервалів. |
| `preset.time_type` | Текстові пояснення кодів стану. |
| `metadata` | Версія схеми, часова зона, джерело та статуси окремих днів. |

У `fact.data` кожен день містить підчерги `GPV1.1`, `GPV1.2`, …, `GPV6.2`.
Кожна підчерга містить 24 години з ключами від `"1"` до `"24"`.
Ключ `"1"` відповідає інтервалу 00:00–01:00, ключ `"24"` відповідає 23:00–24:00.

Кожен код визначає стан двох послідовних півгодинних інтервалів:

| Код | Перші 30 хвилин | Другі 30 хвилин |
| --- | --- | --- |
| `yes` | Світло є | Світло є |
| `no` | Світла немає | Світла немає |
| `first` | Світла немає | Світло є |
| `second` | Світло є | Світла немає |
| `mfirst` | Перемикання, жовтий стан | Світло є |
| `msecond` | Світла немає | Перемикання, жовтий стан |

Для `msecond` перша половина години є червоною, друга є жовтою.
Жовті інтервали передаються окремо й не замінюються зеленими або червоними.

### Статус окремого дня

Статус доступний у `metadata.days["YYYY-MM-DD"]`:

| Поле | Значення |
| --- | --- |
| `status: "scheduled"` | Отримано повну таблицю графіка. Усі її інтервали можуть бути зеленими. |
| `status: "no_outages"` | Джерело прямо повідомило, що застосування графіка не прогнозується. У `fact.data` усі години цього дня мають код `yes`. |
| `status: "unknown"` | Немає отриманого графіка або підтверджених збережених даних. Цей день відсутній у `fact.data`. |
| `verifiedAt` | Час останнього успішного підтвердження саме цього дня у форматі ISO 8601 UTC; `null` для невідомого дня. |
| `fresh` | Чи підтверджено цей день під час збору даних, що сформував поточний файл. |

`fresh: true` не означає, що дані перевірено безпосередньо перед вашим запитом.
Для оцінки актуальності використовуйте `verifiedAt`. При частковій недоступності
джерела раніше отриманий день може зберігатися з `fresh: false` та попереднім
часом підтвердження. Відсутність графіка не означає скасування відключень.

### Дати та часова зона

Усі дати графіків визначаються за `Europe/Kyiv`. Наступний день потрібно
обчислювати як календарну дату, а не додаванням 86400 секунд: тривалість доби
може змінюватися під час переходу на літній або зимовий час.

У разі затримки оновлень `fact.today` може стосуватися попередньої публікації.
У клієнтському застосунку визначайте поточну київську дату самостійно
та перевіряйте наявність відповідного дня у файлі.

## Приклад використання

Отримання графіка підчерги `5.1` на поточну київську дату з перевіркою
актуальності. Поріг у дві години наведено як приклад; його слід обирати
відповідно до вимог вашого застосунку.

```python
import json
from datetime import datetime, time, timedelta, timezone
from urllib.request import urlopen
from zoneinfo import ZoneInfo

url = "https://raw.githubusercontent.com/findme88/poltava-outage-data/main/data/Poltavaoblenergo.json"
with urlopen(url, timeout=20) as response:
    data = json.load(response)

kyiv = ZoneInfo("Europe/Kyiv")
today = datetime.now(kyiv).date()
info = data["metadata"]["days"].get(today.isoformat())
if info is None or info["status"] == "unknown":
    raise ValueError("Графік на сьогодні недоступний")

verified_at = datetime.fromisoformat(info["verifiedAt"].replace("Z", "+00:00"))
age = datetime.now(timezone.utc) - verified_at
if not -timedelta(minutes=5) <= age <= timedelta(hours=2):
    raise ValueError("Час підтвердження графіка не відповідає вимогам актуальності")

day_key = str(int(datetime.combine(today, time(), kyiv).timestamp()))
schedule = data["fact"]["data"].get(day_key, {}).get("GPV5.1")
if schedule is None:
    raise ValueError("Дані для підчерги 5.1 недоступні")
print(schedule)
```

## Локальний запуск

Потрібні Python 3.11+ і база часових зон IANA.
На Windows за відсутності бази часових зон встановіть пакет `tzdata`.

```bash
python -m pip install -r requirements.txt
python -m unittest discover -v
python collector.py
```

Результат записується в `data/Poltavaoblenergo.json`. Неповні таблиці,
невідомі коди станів і непідтверджені дати не публікуються як достовірні дані.

## Обмеження та ліцензія

Набір описує опублікований план, а не фактичний стан електропостачання.
Аварійні відключення та оперативні зміни можуть не відображатися у графіку.
Актуальні офіційні повідомлення оператора мають пріоритет.
